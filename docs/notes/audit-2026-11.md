# Whole-repo audit (2026-11-10)

Every tracked source file was read once, in 63 slices, for what was broken, inconsistent,
inefficient or no longer needed. The fixes landed as three stacked pull requests: Go, then
the frontend with its mock and e2e, then docs, build files and notes.

## Decisions

- Bugs got a test that failed first. Dead code was removed only after a whole-repo grep.
- RPCs and proto fields with no caller in the repo were left in place. A plugin with the
  `api` permission can reach them, and `docs/notes/diff-viewer-3.md` kept one on purpose.
- `docs/PLAN.md` and `docs/perf.md` are gone: both described the app as it was in early
  October. History is in the notes and in git.
- Step notes that nothing outside `docs/notes` cites were read one by one. 114 that only
  repeated what the code and its comments already say, or described removed UI, were
  deleted. The screenshots under `docs/notes` went too: notes are text only, and pull
  request bodies link shots by commit or shots branch, never by `main`.

## Gotchas

- `internal/skills/rules_test.go` cites notes by bare name (`note: "bridge-fix-wording"`),
  so a grep for `docs/notes/<file>` does not find every citation. Check that test before
  deleting a note.
- A wake's fire time is cut to the millisecond and an item's creation time is not.
  `itemsUntil` compared the two as they were, so a message written in the fire's own
  millisecond was read as a later turn and the wake lost its `last_message`
  (`TestThreadWakeDetailDelivered` failed about one run in three).
- `e2e/app.spec.ts` drives the mock-only `worktree.create` command. Nothing else calls it,
  and the daemon has no command of that name.
- `vi.mock("@/api/command")` factories built from `src/test/daemonFakes.ts` deadlock when
  that file imports `@/api/command` at runtime, which is why the error builders live in
  `src/api/commandErrors.ts`.
- `make check` now refuses to record a tree that changed while it ran.
