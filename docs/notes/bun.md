# Frontend toolchain: pnpm and tsc replaced by Bun

`gui/frontend` is installed and driven by Bun (1.4.3 or newer). `bun install --frozen-lockfile`
replaces `pnpm install --frozen-lockfile`, `bun run <script>` replaces `pnpm run <script>`, and
the `typecheck` script is `bun check -b` instead of `tsc -b`. The Makefile's `BUN` variable
and `make bun-version` guard carry this; `gui/Taskfile.yml` tells wails3 the same
(`PACKAGE_MANAGER: bun`, which the Wails template already supported).

## Why

After the oxlint switch (docs/notes/oxlint.md) `tsc -b` was the slowest frontend step that
was not a test: about 10 s warm. `bun check -b` is Bun's built-in TypeScript 7 checker
(a port of typescript-go), 0.3 s on these two projects with the same zero errors. Taking Bun as
the package manager at the same time means one runtime fewer to install for the checker and a
6 s cold install instead of pnpm's.

## What runs on what

* **Bun:** `install` and `check`. Nothing else.
* **Node:** Vite, Vitest, Playwright, and the `tsx`-run scripts (`mock`, `mock:emit`, `themes`,
  `themes:check`). `bun run` respects their `#!/usr/bin/env node` shebangs, so nothing about
  how they execute changed. Node 24 stays a requirement, which is why CI keeps
  `actions/setup-node` next to `oven-sh/setup-bun`.

The mock daemon was tried on the Bun runtime (`bun mock/server.ts`, dropping `tsx`). It serves
requests, and the e2e suite ran, but 17 tests failed on every run and passed again as soon as
the mock went back to Node, same machine, same load (an A/B with 2 load flakes on Node against
17 on Bun). The failures were count mismatches (`expected 1, received 3`: streams, invocations,
intents delivered more than once), pointing at the Connect server-streaming paths of
`@connectrpc/connect-node` under Bun's Node compatibility. Not chased: `tsx` costs one
devDependency and the mock is test tooling.

## Settings carried over from pnpm-workspace.yaml

`bunfig.toml` holds the install policy: `linker = "isolated"` (pnpm's layout, no phantom
imports), `minimumReleaseAge = 604800` (7 days, pnpm's was 10080 minutes),
`minimumReleaseAgeExcludes = ["@wailsio/runtime"]`. The Wails runtime patch is declared in
`package.json`'s `patchedDependencies` with the same key and the same file under `patches/`:
pnpm's git-diff patches apply as they are, verified by the patched `drag.js` text in
`node_modules`. pnpm's `allowBuilds: { esbuild: false }` has no equivalent and needs none:
esbuild is still a Vite dependency and Bun runs lifecycle scripts only for packages it trusts.

## TypeScript 7 semantics, TypeScript 6 package

`bun check` behaves like TypeScript 7.0.2 whatever `typescript` is installed. The `typescript`
devDependency stays at 6.0.3 anyway: `src/design/scan.ts` (the design guards) uses the compiler
API, which TypeScript 7 does not ship yet (the `typescript@7.0.2` package has no usable API
types; `bun check` reported 38 errors in that one file when it was tried). The tsconfigs were
already TS6-style (bundler resolution, `./`-prefixed paths, explicit `types`), so nothing else
differs between the two checkers on this code. The editor's TypeScript 6 and `bun check`'s 7
can disagree in principle; when they do, `bun check` is what CI runs. `tsBuildInfoFile` stays
in the tsconfigs for a manual `tsc` run; `bun check` ignores it and keeps no cache.

## Gotchas

* **Bun must be 1.4.3 or newer.** Older Bun has no `check` subcommand; `bun run typecheck` on
  it says `Script not found "check"`. `make frontend-deps` (and so `make check`) runs
  `make bun-version` first and names the fix (`bun upgrade`). The script is called `typecheck`
  on purpose: a script named `check` is what `bun check` runs instead of the type checker.
* **CI:** `oven-sh/setup-bun@v2` pinned to 1.4.4, `actions/cache` on `~/.bun/install/cache`
  keyed by `bun.lock`. `pnpm/action-setup` and the setup-node pnpm cache are gone.
* Fixture text in the mock and tests (`pnpm dev`, `pnpm --dir web dev`, the
  `ERR_PNPM_FETCH_404` sample) is deliberately unchanged: it models users' repos, not ours.
* `internal/theme/frame.css` is generated by `bun run themes` and its header names the command,
  so the generator and the file changed together; the drift tests pass.
